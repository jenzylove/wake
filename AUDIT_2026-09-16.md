# WAKE repository and build audit

Date: 2026-09-16  
Baseline: `main` at `6a073bc`  
Audit branch: `codex/wake-repo-audit-hardening`

## Executive verdict

WAKE has a strong, differentiable thesis and a convincing investigation surface. The real chain receipts, explicit observed/inferred boundary, causal falsifier, and abstention case are genuinely useful. The build was weaker than its documentation claimed in three decisive areas: consequence numbers were uncalibrated scenarios, the watcher did not discover incidents, and Bitget Demo execution was not connected to a strategy-origin order record.

This branch fixes integrity, safety, and internal-consistency defects. It does not manufacture the missing market evidence. The remaining blockers are product/data work, not frontend polish.

## Severity findings

### P0 — winning-path blockers

1. **No calibrated consequence or position-sizing model.** The AFX `5.4%` consequence, `$1,200` max loss, and `10% of incident VaR` size are hand-authored scenario values. They are deterministic but not derived from captured depth, spread, volatility, slippage, funding, or open interest. A judge can reproduce the text, not the economic calculation.
2. **No strategy-origin Bitget Demo receipt.** The repository had a standalone BTCUSDT adapter smoke test, while the product UI created only a browser-local paper receipt. That proves the adapter can trade, not that WAKE's evidence → falsifier → risk gate → execution chain traded. The route is now incident-bound and ready, but an authenticated run and preserved sanitized receipt are still required.
3. **No live incident discovery.** The scheduled watcher checks configured market/chain adapters and records a pass. It does not discover a new exploit, create an incident, build its graph, or advance the state machine automatically.

### P1 — high judging and reliability risk

1. **Execution-quality market evidence is absent.** Every captured Bitget mark candle reports zero volume; the packets do not contain bid/ask spread, funding, open interest, depth, or slippage. The current gate therefore cannot substantiate the PRD's liquidity checks.
2. **The key AFX market edge is inferred.** The outflow receipt is real, but the downstream conversion, venue arrival, and ETH sell trace are not fully captured. That keeps the most important ActionGraph edge below observed status.
3. **Hosted runtime history depends on configuration.** Browser observations are intentionally session-only. Protected server writes become durable only when private Blob storage is configured.
4. **Evidence sample is too small for outcome claims.** Three captures can demonstrate the workflow, but not predictive quality, calibration, or growth across incident classes.

### P2 — credibility and maintainability defects fixed on this branch

1. Public mutation routes could fail open when secrets were absent; Demo order input allowed arbitrary symbols and sides.
2. A blocking recovery falsifier could coexist with a displayed `TRADE_RESOLUTION` recommendation.
3. Generic graph construction mislabeled unrelated relationships as `collateralizes`.
4. `data:verify` checked only a self-contained hash, not receipt, timestamp, or candle invariants.
5. Anthropic references outside the packet were silently removed instead of rejecting the response.
6. A hardcoded Cloudflare IP was used even when no DNS workaround was configured.
7. The README contained duplicated starter-template documentation; the UI claimed a fake verified agent key and showed one capture despite three real packets.
8. There was no test command or CI workflow.

## Fixes in this branch

- Hosted Demo orders, observation writes, and scheduled watcher runs fail closed without the appropriate secret.
- Demo opens require a known incident, a trade decision, a passing deterministic gate, Bitget contract compliance, and a configurable notional cap. Instrument and direction are derived server-side.
- Blocking falsifiers force monitor/no-trade. The AFX response case can no longer present a conditional recovery request as an approved long.
- Each real capture has incident-specific ActionGraph edges and explicit evidence semantics.
- Scenario percentages are visibly labeled `not calibrated` rather than presented as a calibrated model.
- Capture verification now checks schema, successful receipt, transaction identity, ordered/in-window candles, OHLC consistency, incident/window alignment, and SHA-256 integrity.
- The AI reviewer must return the exact six falsification keys and may cite only evidence references from the supplied packet.
- Public mark monitoring remains usable without granting anonymous durable-write access.
- CI now covers lint, typecheck, policy tests, capture validation, and production build.

## Rubric assessment

| Dimension | Verdict | Why |
| --- | --- | --- |
| Clear thesis | Strong | “Evidence before execution” and causal consequence mapping are specific and easy to explain. |
| Runnable end-to-end demo | Partial | Replay is runnable; autonomous discovery and strategy-origin Demo execution are not yet demonstrated together. |
| Verifiable usage/trading records | Partial | Chain and market captures verify. Local paper receipts are reproducible, but an exchange-issued strategy receipt is still missing. |
| Completeness | Partial | UI and core evidence flow are broad; the economic model and watcher automation stop before the hardest parts. |
| Genuine novelty | Strong | ActionGraph plus falsification is more original than a generic signal bot or LLM trader. |
| Growth potential | Strong if resolvers become real | The graph/resolver architecture can expand by protocol and event class; current discovery coverage is too narrow to prove that yet. |

## Exact next sequence

1. Capture order-book spread/depth, funding, open interest, and a tradeable-volume estimate at incident time or through a reproducible historical provider.
2. Replace the AFX scenario percentage and string size with a documented calculation that outputs quantity, entry assumption, stop, fees, slippage, and maximum loss.
3. Run the incident-bound Demo route with the operator secret, preserve the sanitized Bitget order ID and preflight, then close and preserve the close receipt.
4. Implement one real resolver that discovers a new event from logs rather than loading a known transaction hash.
5. Capture the full AFX downstream flow or use a different event whose market-impact path can be proven end to end.
6. Configure private Blob storage and an external 1–5 minute scheduler if Vercel Hobby cadence is retained.

Until steps 1–4 are complete, WAKE is an excellent causal investigation prototype—not yet a defensible autonomous agentic-trading system.
